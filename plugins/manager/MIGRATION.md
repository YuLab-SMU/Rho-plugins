# Manager 场景与组合能力迁移要求

Manager 接收从 Core 退出的场景定义、历史、准备和组合编排。Studio 是这些能力的
另一个消费者，不保存第二份场景权威状态。当前 Manager 是纯 UI 插件，清单的
`backend` 为 `null`；现有场景实现仍在 Core。本文件是待实施要求，现状见
[README](README.md)，不表示组合后端已经实现。

## 所有权和公开入口

在现有 Manager 包中补齐组合能力后端，拥有场景定义、版本和准备状态。UI、Studio
以及外部调用方使用同一公开契约。具体能力名称和存储由选定流程确定，不预建新的
共享插件。以后若确有多个消费者需要独立组合包，仍保留本文件的能力保留要求。

Core 继续拥有包、实例、授权、资源和原 Operation。Manager 通过公开能力执行
每一步实例动作；工作流状态引用这些原记录，不增加第二套执行账本或新的审批系统。
布局持久化、焦点和对当前窗口的应用归 Rho 外壳；Manager 保存可引用的组合意图，
双方在接入时明确窗口与实例的身份、版本和可见范围。

## 必须承接的用户能力

| 用户动作 | 迁移后必须保留的结果 |
| --- | --- |
| 查看、编辑和保存场景 | 精确包与产物、alias、配置、Provider 绑定、资源上下文和布局意图可定位 |
| 查看或恢复旧场景 | 读取旧版本不改变 head；恢复创建新版本并检查当前 head，不回滚科学副作用 |
| 准备场景或新 R 工作区 | 明确选择已有兼容实例／视图或新建；固定依赖；未准备成功的部分保留可检查 |
| 应用到当前窗口 | 对外壳捕获的当前布局版本检查，失败保留原布局；准备与应用分别确认 |
| 刷新、重开或处理丢失回报 | 读取每一步原请求，不自动开始下一步、不重复激活或用替代实例填补缺口 |
| 管理部分准备结果 | 显式查看、继续或清理；开始新表单不自动释放已创建实例 |

未保存的场景 JSON、无效文本、初始视图状态和捕获 head 也由 Manager 保留。
草稿确认与有效场景保存分别表达；切换选择或重开视图不能丢弃尚未保存的编辑。

当前依赖的 `scenarios.*` 和产品性的 `windows.scenario` 需要相应承接入口。
准备新 R 工作区仍不启动 R、安装缺失科学包或偷偷选择其他 Provider。场景恢复也不
回滚文件、R 内存、凭据或输出。隐藏并复用视图时，当前未保存内容保留。

安装包检查、导入导出、不可变身份、实例读取、恢复和释放继续使用 Core 的公开能力。
受确认的实例恢复与场景准备分别处理；不能借本次迁移重放原科学工作。
开发分支相关动作由 Studio 承接，Manager 若保留入口则调用其公开能力，不另建源码仓库。
科学 Packages 查看保持只读；安装不属于本文件新增职责。

## 状态和失败处理

保存定义、准备和应用各自有版本及原 Operation 引用。新的 UI 状态不能覆盖未确认的
原请求；替换视图可受授权检查旧记录，不能以新调用者身份自动重试。
部分失败、Owner 缺失、旧记录可读但实例不可观察、清理未确认分别报告。
只有所选流程依赖的缺口影响继续操作，不冻结其他场景查看、读取或独立分析。

场景历史、原始定义、准备映射和已创建身份不能随 Core 表退出而删除。旧内容的受授权
读取、导出或显式迁移是单独任务；保留字节但没有访问入口时仍列为未完成。
状态大小、历史分页和并发准备的资源限制需说明保护对象、配置及超限行为。

## 实施和验收

先以外部调用方保存一个明确组合并准备精确实例，再接入 Manager 和 Studio。
后端流程不要求 Manager 窗口存在；窗口应用经外壳的公开入口接入并另行验证。
普通 Core 与科研调用不依赖 Manager 已安装。

所选真实组合需要验证：准备不启动 R；部分失败不替换实例；丢失回报不重放；
旧 head 或布局版本拒绝冲突写入；切换失败保留原窗口和草稿；原实例与其他窗口不被
隐式释放。窗口行为和代表性宽度由应用侧验收，后端构建不代替这些证据。
完成后分别记录组合后端、两个 UI 消费端及应用组合中哪些流程已经通过。
