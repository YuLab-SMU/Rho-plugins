# Console 输入与视图状态迁移要求

Console 保留命令输入和呈现状态，承接 Core 产品视图状态收缩后的内容责任。
这是待实施要求。当前 Console 是纯 UI 插件，输入通过有确认的视图状态保存，
并非 `documents.*` 草稿消费者；不为迁移预设一个新的 Console 文档服务。
当前行为见 [README](README.md) 和 [模型](src/model.ts)。

## 所有权和接入

Console 拥有命令输入、选择、有限命令历史、滚动和 transcript 呈现语义。
应用外壳提供选定的状态保存与确认路径；若现有机制已足够，优先复用，不要求
另建后端或数据库。布局、窗口和凭据归外壳；R 会话、stdin 请求和执行队列归 R；
原 Operation 与幂等归 Core。关闭 Console 不停止原生 R 或已受理工作。

## 必须保留的能力

- 未发送命令、Unicode 内容、选择和已确认输入历史在关闭重开后仍能恢复。
- 保存失败可见；突然断线不能把尚未确认的输入当成保存成功，迟到回执不能覆盖新输入。
- 固定原 R Provider 和会话。它不可用时仍能查看保留记录，不自动选择另一实例或重启 R。
- 运行记录由原 Operation、有序事件和带摘要的保留事件重建；Clear View 不删除原记录，
  Show History 不执行代码。当前显示上限为 100 个完成 run 加活动工作，原历史另行可查。
- 丢失提交回报时保留原代码、请求、调用者和目标供显式检查；重开或替换视图不自动提交。
- stdin 与命令草稿分开，stdin 回答保持临时性，不存成可重放命令，也不在重连后重发。
- 排队取消、运行中断和原结果结算分别呈现；状态缺失不表示执行停止。

状态恢复不能通过布局版本变化重置输入。隐藏或移动视图应保留当前 DOM 和未确认
内容；真正关闭使用明确的保存确认。应用只传输受授权的状态，不解释或执行命令。
内容、历史和事件分页的限额需说明保护对象、配置与超限行为，超限不能静默丢命令。

## 实施和验收

先接入外壳选定的持久化与确认机制，验证 Console 内容，再验证真实 R 连接的连续性。
旧已确认状态的受授权读取、导出或显式迁移另行选定；不能只删除旧 Core 表或保留不可
访问的字节后宣布恢复完成。窗口导航变化不得扩大科学权限。

用临时项目验证未发送 Unicode 命令的刷新与关闭恢复、保存失败提示、移动视图后保留
输入、原 Provider 不可用时记录仍可读、丢失回报不重放，以及 stdin 不被重发。
真实 R 流程另外确认关闭视图后会话与活动 Operation 持续存在；UI 状态夹具不能代替
这一结论。验证不重启用户 Host 或 R 会话。
