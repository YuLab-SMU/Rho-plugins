# Studio 能力迁移与保留要求

Studio 接收从 Core 退出的插件源码开发、构建、预览、测试编排和开发草稿能力。
这是待实施要求，目标是 Core 收缩后开发者仍能完成这些动作，并保留内容与执行记录。
当前 Studio 是纯 UI 插件，清单的 `backend` 为 `null`，实际工作流依赖 Core；
本文件不表示后端或迁移已经实现。现有行为见 [README](README.md)。

## 所有权和公开入口

在现有 Studio 包中增加所需开发后端，能力契约归 Studio，UI 与外部 CLI、MCP 通过
同一公开能力调用。先复用文件、Git、现有构建工具和 Core 的受管执行，不建立第二套
Operation 日志，也不要求普通科研流程加载 Studio。文件访问继续受项目及授权约束。

Studio 拥有源码工作区、开发草稿、构建选择、预览配置和测试编排状态。场景定义与
准备流程归 [Manager](../manager/MIGRATION.md)；Studio 通过其公开能力应用所选产物。
窗口布局、视图托管和私有凭据归 Rho 应用外壳；包校验、实例授权和执行日志归 Core。
新的能力名称和具体存储在选定实施流程时确定；旧接口名称只是当前依赖，不是兼容要求。

## 必须承接的用户能力

| 用户动作 | 迁移后必须保留的结果 |
| --- | --- |
| 编辑源码或声明 | 保留未保存和无效文本、Undo、原始文件字节及当前基线；编辑不触发构建或激活 |
| 保存检查点或恢复历史 | 检查捕获的 head；冲突时保留编辑并允许从旧基线另建分支；恢复产生新记录 |
| 构建指定源码 | 固定源码和工具输入，返回精确产物身份、原 Operation 与有界诊断；不自动安装工具 |
| 停止或检查构建 | 分别表达停止请求与确认结果；超时、截断、丢失回报和 `Uncertain` 保留原身份 |
| 预览指定视图 | 固定产物、配置和 fixtures；不启动科学后端、不授予科学权限、不回退到项目读取 |
| 创建和停止后端测试 | 使用独立临时项目、catalog、Host 及精确依赖；不复用当前分析会话 |
| 重开 Studio 或查看旧任务 | 恢复已确认开发内容并读取原任务；不自动重跑或用新实例冒充旧实例 |
| 将产物用于场景 | 经 Manager 保存、准备再应用；每一步分别记录；部分准备保留，不隐式回滚科学状态 |

当前源码工作流调用 `plugins.branch*`、`plugins.checkpoint`、源码读取与比较；构建和
预览调用 `plugins.build`、`plugins.preview`；测试调用 `plugins.test_*`。
这些能力退出 Core 后，Studio 的用户动作仍需有明确入口。只读不可变包查看、包导入
导出和实例生命周期继续调用 Core；不能因开发迁移把它们复制成 Studio 私有平台。

## 内容和执行状态

开发草稿包含源码、声明、无效表单、预览 fixtures、捕获基线和待确认的原请求。
保存草稿的确认与保存检查点、构建成功及磁盘保存分别表达。Typing 产生的新内容不能
被迟到回执覆盖。替换视图可以受授权读取旧请求，不能改变原调用者后自动重试。
源码分支历史与当前未保存内容分别保留；Git 本身不证明草稿已经保存。

画布模型、声明解释和编辑历史归 Studio。画布保持惰性；可执行预览使用独立受限路径。
自定义源码、绑定和不支持的组件不得因模型退出 Core 而静默丢弃或执行。
运行呈现是否复用具体组件模型，由选定 UI 消费端验收，不扩展为 Core 通用契约。

构建后端与测试调用方分别确认原生进程身份和清理。关闭 Studio 窗口不等于取消任务；
查询不创建或恢复测试 Host。停止后仍可定位测试原日志和子 Operation。
无法确认清理时保留身份和诊断，不自动替换或删除临时项目。
Core 自身的协议测试由外部测试工具编排，不以安装 Studio 为前提。
构建与测试启动使用明确的原授权；子 Host 的 scope 由受授权的启动方选择，
配置、清单和测试请求不能扩大调用者已有权限。

内容、历史、构建输出、队列和测试资源各自需要明确限额，说明保护对象、配置位置与
超限行为。迁移前记录已有受支持容量，变化需说明；超限不能静默截断可编辑源码。
关闭握手只承诺已确认内容；未确认内容保留诊断和恢复机会，不能标为已保存。

## 实施和验收

先选择一个真实动作实现后端及公开契约，再接入 Studio UI。源码、构建、fixture 预览、
测试 Host 和场景调用可以分别交付；未接入的入口明确显示缺失 Owner，不假报成功。
现有内容的读取、导出或显式迁移另行选定，不能直接读取 Core 私有数据库或自动清理。
内置 Agent 的退出属于另一个已选方向，不要求在这里新建替代聊天或迁移 Agent 数据。

验收至少覆盖所选路径的真实源码与产物、冲突后的内容保留、丢失回报后的原请求读取、
视图关闭后任务状态，以及受授权的停止和清理。测试项目使用可丢弃目录；
不重启用户 Host 或 R 会话。预览验收还需确认科学调用和外部访问实际被拒绝。

只有后端和真实 UI／外部调用流程通过后，才可声明该项产品能力已接替；Core 的接口
退出或 Studio 的构建成功不代替验收。组合由应用仓库显式选择版本、SDK 和产物。
