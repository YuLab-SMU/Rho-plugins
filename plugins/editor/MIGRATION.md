# Editor 内容与草稿能力迁移要求

Editor 接收从 Core 通用草稿服务退出的编辑内容、版本和恢复责任，保留用户在外部
文件变化后安全继续工作的能力。本文件是待实施要求，不表示草稿存储或消费端迁移
已经完成。当前 [后端](backend/src/server.rs) 和 [草稿同步](src/draft-sync.ts)
依赖 Core 的 `documents.*`；真实文件读取与写入继续由 Files 拥有。

## 所有权和公开入口

Editor 拥有文档身份、未保存内容、内容版本、选择、磁盘基线以及编辑、保存和运行的
捕获。将需要的草稿能力放到现有 Editor 后端，UI 和外部调用方使用相同公开契约。
文档可定位不要求打开 Editor 窗口；访问仍检查项目、调用者、权限和明确的原 Owner。
窗口连接身份与内容身份分别处理，去除窗口依赖不能去掉原来的授权检查。

Files 拥有磁盘观察、内容身份、路径保护和写入前置条件；R 拥有原生运行与会话。
Core 拥有受管执行及原 Operation。Editor 不复制文件系统服务、科学运行时或执行日志。
Studio 的源码草稿与 Console 输入由各自 Owner 负责，不统一搬到 Editor。

## 必须承接的用户能力

| 用户动作 | 迁移后必须保留的结果 |
| --- | --- |
| 新建或修改文档 | 未保存内容、无效文本、Unicode、选择及版本可恢复，确认与本地修改分别表达 |
| 关闭或重开视图 | 已确认草稿仍可定位；关闭不丢内容、不重放保存或运行；未确认内容不标为已保存 |
| 从外部调用编辑、保存或运行 | 捕获明确文档版本、内容、选择、目标文件／会话和权限；不依赖模拟 UI 点击 |
| 保存时发生外部修改 | 保留草稿、旧基线和新的 Files 观察；比较、合并或另存后继续，冲突覆盖被拒绝 |
| 读取新磁盘内容或建立新分析基线 | 新观察不冒充旧版本；按当前用途检查必要输入，无须补齐全部编辑历史 |
| 处理迟到或丢失回报 | 保留原 Operation；迟到编辑不覆盖新草稿，检查结果不自动重试 |

保存草稿的确认不等于文件已写入，文件写入不等于运行成功。Editor 的内容版本只约束
该文档，不是项目或科研全局 revision。普通文件操作也不要求创建 Editor 草稿。
当前 `documents.list/read/inspect/stage/save` 的消费路径应由 Editor 自有入口接替；
具体契约在选定流程中确定，不维护 Core 旧接口的私有副本。

## 外部变化和继续工作

Editor 通过 Files 的当前观察检查必要的目标与内容身份。发现磁盘从 A 变为 B 时，
记录新观察及差异，不伪造中间修改 Operation，也不推断修改者。
已有草稿时保留 A、B 与草稿供比较；安全合并失败只阻止冲突覆盖，仍可查看、另存或
选择新基线。自动刷新不能丢掉编辑、改写历史捕获或把 B 当成旧运行使用的 A。

原动作 `Uncertain` 时，后续读取和独立工作仍可进行。对同一目标再次写入或同一原生
会话运行，要检查原请求及 Owner 的当前前置条件；当前内容符合预期不能证明旧动作
已经确认。未知会话状态不能借建立新文档身份绕过。

## 内容保存与旧数据

已确认内容及其来源、捕获、历史和未确认请求需要保留。Owner 存储与授权读取、导出
或显式迁移路径另行实施；不能直接读取 Core 私有数据库或在移除服务时自动清理。
新视图可以受授权查看旧请求，不能冒用原视图身份重试。

内容、传输、编辑历史和并发修改分别说明资源限额、配置及超限行为。只读预览、
可编辑内容和保存输入的完整性分别验证；不得把截断预览保存为完整文件。
Git 提供已提交历史，不能代替未保存内容和并发写入检查。

## 实施和验收

先实现一次可定位的内容捕获、编辑与查询，验证外部调用，再接入 UI 恢复和真实 Files
保存。保存和运行继续委托各自原 Owner，不捏造文件结果或 R 结果。
使用临时项目检查：输入 Unicode 后关闭重开；外部改盘后比较与另存；过期版本被拒绝；
迟到回执保留新编辑；断线后原 Operation 可读且不重放；无窗口调用仍受原 scope 约束。

真实草稿恢复、文件冲突和 UI 行为通过后，才可声明对应能力已接替。Core 草稿接口
退出、Editor 编译通过或仅保存了旧字节不代替这些结果。应用接入单独选择 SDK 和版本。
