# Rho-plugins：真实领域试用与重建边界

决策日期：2026-10-11；主分支边界更新：2026-10-12。先归档旧代码、落实重建规则，
再用真实 R 分析检查新 Core 的受管价值。领域试用和评估插件迁移已在限定范围
验收；main 已移除旧资产，新的科学插件全面重写尚未开始。
2026-10-12 补充选择：Agent 评估与改进实验作为可供其他插件复用的独立插件能力；
随后按用户要求迁入现有评估工具，并交付公共二进制调用与 R 产物核验复用；
候选改进、盲测管理和应用接入尚未实现。

## 旧实现与主分支

2026-10-12 用户明确要求主分支只保留新插件仓库内容。完整受控旧源码已发布到
[`codex/legacy-plugins-before-rebuild`](https://github.com/YuLab-SMU/Rho-plugins/tree/codex/legacy-plugins-before-rebuild)，
远端分支头和根树已与本地备份核对。从 main 移除的旧文件，其内容摘要与文件模式
全部与该备份一致；本地忽略的构建缓存、证据与用户数据不属于源码备份。

`main` 现在只保留已选择的新工作：Agent 评估插件、真实 R 分析配方与领域核验、
验收记录和当前仓库说明。旧十六包、旧 Core 的 `crates/`、`sdk/`、`core-sdk.json`、
旧 Cargo／前端清单、构建脚本、Jet 源码与补丁、旧运行材料和技能均离开 main。
此变化使用普通后续提交，保留 Git 历史；归档只用于回答具体需求或失败。

旧包与旧设计不是必须恢复的产品清单。后续工作继续使用选定的公共 Core CLI、
R／原生工具及普通文件，不刷新旧快照、更新应用锁、提供兼容层或迁移旧 catalog。
科学插件全面重写、统一装载和应用接入仍按真实需求分别选择。

## 先跑真实分析

用户动作：Agent 通过已有 `rho-core` CLI 提交一段有真实研究问题和公开数据的 R
分析；等待中断后找到原操作与仍在执行的分析，继续观察并取回产物，再按预先明确的
分析行为和独立核对结果验收。研究方法由领域 Owner 判断，Core 不判断科学结论。

本轮选定 [真实 R 试用](../examples/real-r-analysis/README.md)：使用 airway/GSE52778
数据检查地塞米松处理的转录响应，按供体配对执行 DESeq2 主分析，并用
leave-one-donor-out 检查结果对单个供体的敏感性。使用维护中的 R 工具和原始领域接口，
无需先把每种统计方法注册为 Core 能力或建立插件 Provider 框架。

试用至少保留以下可核对材料：

- 数据来源、实际输入及其摘要、研究设计、完整分析脚本和实际 R／依赖版本；
- 原请求与操作身份、真实进程或会话关联、已知执行状态及仍无法确认的部分；
- 等待中断前后找到同一任务的证据、派发次数与取回的原输出，不能重跑来补造回报；
- 完整数值表、图和其他科学产物，以及内容摘要、可读性和独立结果检查；
- 失败、部分结果、取消或缺失材料，并分别给出执行事实与科学验收结论。

分析所需时间来自实际计算；不添加休眠来伪造长任务。输出文本不自动等于产物已经
完整保存；观察到当前文件也不自动证明它是某个旧操作的历史产物。来源与因果只按
实际记录表达。等待者中断、分析中断、宿主崩溃和 R 会话恢复分别验收，不扩大 Core
[现有受管运行契约](https://github.com/YuLab-SMU/Rho-core/blob/main/docs/MANAGED-RUN.md)与
[宿主／CLI 契约](https://github.com/YuLab-SMU/Rho-core/blob/main/docs/HOST-CLI.md)的保证。

Core 自带的分析试点和夹具可以证明其公开调用行为，不能替代这项领域 Owner 的真实
结果与产物核验。构建通过、退出码成功、Agent 自述和旧应用验收也不替代这些证据。

## 两项优先 Owner 职责

本轮 `rho-airway-03` 完成五次真实数据拟合，以及 200 次全基因负二项参数模拟
重拟合，R 实际运行 562.6595 秒（9 分 23 秒）。独立 wait 客户端被 SIGTERM 中断后，
CLI 找到原活动 run 与 R PID；重复提交仍返回原 run，原生入口只有一次。终态 Code 0、
已释放、文本完整；原目录与取回副本各 12/12 独立数值／完整性检查通过，五个 RDS
另有 121/121 原生观察检查。四页科学图已检查，自己的 Host 正常清理。

主分析 4,068 个基因 BH < 0.05，六个预选响应基因在五次真实拟合中均为正；模拟
分位数只描述固定四供体及拟合模型下的计数变异，不是种群或临床置信区间。方法、
数值、原始身份、独立检查的限制和证据位置见[事实验收](../examples/real-r-analysis/ACCEPTANCE.md)。

01 的 socket 启动失败、02 的短分析与核验器未就绪导致的收尾失败均保留。02 后来
对原产物的 11/11 检查通过不覆盖原驱动失败；03 用新请求承载新增模拟工作，没有
重跑来替换原失败。已补上核验入口预检。三个副本反例均被拒绝，包括重算摘要后
伪造的 BH 值。这些事实支持先完善消费端分析配方，没有显示 Core 的共同缺口。

当前后续工作收敛为以下两项领域职责，不据此确定新插件包数量。

### 1. R 批分析配方

用户提交明确的数据、脚本与参数，在原 R 进程中完成分析，取回实际 R／包版本、
拟合模型、错误与部分结果。先完善可复用的分析配方、原生条件、资源边界和核对说明，
继续使用维护中的 R 工具与 Core 已有 CLI。03 已说明这条路径无需先创建 R 会话包。

反证与扩张条件：如果实际任务用一个 Rscript 进程及保留的 RDS 就能完成，新建
R-session 包没有新增价值。只有后续任务确实需要定位已有交互 R 内存、处理其输入
或检查原对象身份，而原工具不能提供必要保证时，才单独选择最小原生会话适配。
等待接续不等于宿主替换后的 R 内存恢复，不因 bootstrap 时间较长增加会话平台。

### 2. 科学产物完整性、来源与取回

用户从原 run 找到它实际选定的输出目录，检查完成声明、产物清单与摘要，再通过
普通文件工具读取或复制数值表、图和拟合模型，并核对复制后的字节及科学事实。
Owner 负责清单含义、来源关联和独立核验；Core 的有界 stdout 继续服务执行回报，
不被宣称为科学文件的保存服务。03 的原目录和取回副本核验已经通过；取回清单
含 31 项产物，共 183,546,739 字节，另外保留 manifest 与 complete。

反证与扩张条件：完成标记、manifest 和普通文件工具已经可以承载这条取回流程，
没有证据要求全局 artifact registry。若后续真实任务在跨环境取回、保留或可变来源
上失败，再描述原文件、身份、缺失行为和必要保证，修正实际 Owner 的最小缺口。
不为普通文件读取重新建设 Files 平台，也不将文件名相近推断为科学来源。

## Agent 评估与改进插件

用户动作：对选定 Agent／配方运行一组明确任务，读取实际调用与原生结果，比较
基线和候选改动，并让其他领域插件复用同一评估入口。用户已选择将这项能力归于
Rho-plugins；它是上述两项科学职责之外的共用评估能力，不是 Core 的模型循环。

### 职责与复用边界

- 评估插件负责用例组织、隔离试次、执行既有调用器、调用核验器、汇总结果与保存
  必要证据。各领域 Owner 提供输入准备、原生条件、结果核验和科学解释；评估插件
  不接管 R 模型语义，也不以统一分数代替领域验收。
- Core 自身的确定性运行、持久化、并发送达和故障回归仍由 Core 仓库拥有，普通
  构建和检查不依赖评估插件、模型凭据或相邻源码。
  [Claude Code 评估工具](../plugins/agent-eval/core-agent/README.md)已从 Core 迁入插件。
  CLI 模式只需调用方显式选定的公共二进制，从实际能力读取契约；不读取 Core 私有
  源码或默认构建目录。Core 自身 Rust 回归和最小库调用示例留在原 Owner。
- 首个复用流程采用普通用例文件、可调用脚本和结果文件，复用既有 CLI／原生工具；
  不先建立 Provider 框架、新插件协议、SDK、全局测试注册表或自动改进常驻服务。
  调用者提供固定的被测版本和制品身份，不导入其他仓库的私有实现。

### 评估与改进是两个显式动作

评估先固定用例、成功条件、被测 Agent／配方、环境、模型配置与评分器版本，再在
新临时项目中运行独立试次。报告区分执行事实、领域检查和模型判断；确定性事实
优先用代码与原生结果检查，开放质量才选择经领域人工样本校准的模型评分器。
模型评分不能覆盖原生失败或科学限制。超时、异常、中断和缺失证据保留在分母中，
未评分项明确为未评分；不默认收集隐藏推理、凭据或整个 Agent 环境的历史。

改进实验在已有基线上明确目标和允许修改的文件／配置，每轮只提出一个可归因的
Git 改动，比较后保留或回退。优化器读取开发集的诊断，验证集用于候选比较，另留
最终盲测集做终验；盲测答案和逐例诊断不暴露给优化器，不把失败原文贴入提示词。
反复参与选择的验证集不能继续声称为未见终验集。评分器校准与候选改进分别记录；
改评分规则须用新版本重评分保留的原材料，不能覆盖原报告或省略失败来提高成绩。
收益在试次波动内时报告证据不足。实验结果是候选补丁与证据，不隐式改变 Core
契约、合并 PR、发布、安装或重启用户运行环境；源码修复仍走实际 Owner 的核验流程。

执行前声明用例、重复次数、模型和改进轮数；显式限制所保护的试次进程、总运行时间、
模型调用／token 预算与证据保留量，并说明可配置项和超限停止行为。额度耗尽时停止
新增试次，终止或取消本次拥有的任务，保留失败与部分报告；费用估算不当作账单。
不建立 Agent 整个环境的全局配额系统。

### 首个可观察交付与当前限制

同一入口能够运行现有 Core CLI Agent 场景与一个 R 配方的领域检查，分别调用各自
Owner 的核验器，保留版本、原材料、分母和未评分范围，并在不调用模型、不重跑原
分析的情况下重评分已有兼容材料。验收必须实际证明这两个消费者的复用，以及超时、
评分失败和改动回退；不以新增目录或搬走文件作为完成。

当前 Core CLI Agent 评估与真实 R 脚本消费者是不同证据。R 输入、分析与科学核验
通过，不等于模型自主选方法、编写并完成该研究任务已经通过；首个复用也不自动
证明跨领域自我改进有效。[评估插件入口](../plugins/agent-eval/README.md)已迁移并实现
上述两个消费者的评估复用、原 Agent 证据重评分、核验失败与资源超限报告。
候选补丁比较、Git 回退、开发／验证／盲测管理及 hillclimb 仍是后续设计；首个完整
改进流程尚未验收。实际迁移证据与限制见[迁移验收](../plugins/agent-eval/ACCEPTANCE.md)。

方法参考：[Automating eval design and hillclimbing with Claude](https://claude.dev/blog/automating-eval-design-and-hillclimbing/)
（原文标注 2026-09-28）和
[Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。
采用其贴近真实任务、校准评分器、隔离评估材料和逐次改动的原则；上面的三集划分、
Owner 分工和发布边界是本项目的选择，不声称文章或现有实现已提供这些保证。

## 按事实选择后续变化

先记录用户做了什么、实际发生什么、期望结果、可复现材料、限制属于谁，以及已有
工具为何不能满足。一个环境未装好或已有命令用法错误，不直接构成新插件的理由。
只修选定 Owner 的最小缺口，并保留对应回归；不因试用涉及多个工具就预建统一平台。

本轮试用的已通过、失败和未验证边界见事实验收。后续按用户价值、失败频率与
必要保证选择实际改动。已有 Rscript、R 包、文件工具、Git 或原生任务句柄
足够时直接复用；没有证据就不新增机制。领域方法说明和可调用脚本可以先交付，
不要求先做视图、统一发现服务、MCP／HTTP 入口、编辑器、管理工具或替代聊天产品。

## 仓库责任与后续验收

| Owner | 本轮与后续责任 |
| --- | --- |
| Rho-core | 已声明的受管受理、请求身份、执行持有、事实读取与不重放；只修复真实调用证明的共同缺口 |
| Rho-plugins／实际领域 Owner | R 方法、原生对象与条件、输入和产物语义、科学核对，以及有证据必要的原生适配 |
| Rho-plugins／评估插件 | 可复用的 Agent 评估与显式改进实验；调用领域核验器，保留证据与评分范围，不接管领域语义 |
| Rho 应用 | 选定组件的装配、界面与产品接入；不另建科学执行路径 |
| Agent 环境 | 阅读资料、编写与组合代码、选择工具、管理模型上下文和检查实际反馈 |

三仓独立交付。插件任务不把应用可运行、旧 SDK 刷新或整套旧包通过作为门槛；应用
任务也不能用自己的展示状态解释 R 的执行结果。选定跨仓集成时再明确公共边界、
组件版本、产物与验收，不依赖浮动主分支，也不把单仓通过扩大为完整组合通过。

使用临时项目与独立宿主，不重启用户的 Host 或 R 会话。代码变更做必要的 Owner
行为检查，Cargo 构建和测试串行运行；复用适用的已验证产物。文档变更检查链接和
渲染内容。保留失败、超时和未执行事实，不为得到全绿反复重跑或放宽权限。

旧 Studio、Manager、Editor 与 Console 移交清单只在
[归档插件目录](https://github.com/YuLab-SMU/Rho-plugins/tree/codex/legacy-plugins-before-rebuild/plugins)
保留，供具体需求参考。当前不按这些历史清单建立后端或迁移旧状态。
