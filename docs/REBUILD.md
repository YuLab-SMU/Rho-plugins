# Rho-plugins：真实领域试用与重建边界

决策日期：2026-10-11。当前动作是保留旧代码、落实重建规则，并用真实 R 分析检查
新 Core 的受管价值。领域试用已在下述限定范围验收；插件重建尚未开始。

## 旧实现与主分支

旧源码已在本地分支 `codex/legacy-plugins-before-rebuild` 保留。分支尚未推送；创建
本地分支、提交文档与发布源码是不同结果。旧提交、分支来源和发布状态通过 Git 核对，
不在工作规则中维护提交清单。

后续新工作在 `main` 按选定流程交付。当前主分支仍保留旧源码，尚未清空或重新实现。
十六个旧包、旧测试和旧设计是可查的历史材料，不是必须恢复的产品清单。仅在一个具体
需求或失败需要回答时查看旧实现，不按旧子系统地图搬运代码。

`crates/`、`sdk/`、`core-sdk.json` 与现有构建流程使用旧 Core 的导出依赖。它们不能
代表新 Core 的接口。本轮不刷新这些快照，不更新应用锁，不为旧消费者提供兼容层，
不迁移、导出或清理旧 catalog、项目和已保存内容。未来确有旧数据需求时另行选择；
本轮使用新建项目与存储。

## 先跑真实分析

用户动作：Agent 通过已有 `rho-core` CLI 提交一段有真实研究问题和公开数据的 R
分析；等待中断后找到原操作与仍在执行的分析，继续观察并取回产物，再按预先明确的
分析行为和独立核对结果验收。研究方法由领域 Owner 判断，Core 不判断科学结论。

本轮选定 [真实 R 试用](../examples/real-r-analysis/README.md)：使用 airway/GSE52778
数据检查地塞米松处理的转录响应，按供体配对执行 DESeq2 主分析，并用
leave-one-donor-out 检查结果对单个供体的敏感性。使用维护中的 R 工具和原始领域接口，
无需先把每种统计方法注册为 Core 能力或建立插件 Provider 框架。

试用至少保留以下可核对材料：

- 数据来源、实际输入及其摘要、研究设计、完整分析脚本和实际 R／依赖版本；
- 原请求与操作身份、真实进程或会话关联、已知执行状态及仍无法确认的部分；
- 等待中断前后找到同一任务的证据、派发次数与取回的原输出，不能重跑来补造回报；
- 完整数值表、图和其他科学产物，以及内容摘要、可读性和独立结果检查；
- 失败、部分结果、取消或缺失材料，并分别给出执行事实与科学验收结论。

分析所需时间来自实际计算；不添加休眠来伪造长任务。输出文本不自动等于产物已经
完整保存；观察到当前文件也不自动证明它是某个旧操作的历史产物。来源与因果只按
实际记录表达。等待者中断、分析中断、宿主崩溃和 R 会话恢复分别验收，不扩大 Core
[现有受管运行契约](../../Rho-core/docs/MANAGED-RUN.md)与
[宿主／CLI 契约](../../Rho-core/docs/HOST-CLI.md)的保证。

Core 自带的分析试点和夹具可以证明其公开调用行为，不能替代这项领域 Owner 的真实
结果与产物核验。构建通过、退出码成功、Agent 自述和旧应用验收也不替代这些证据。

## 两项优先 Owner 职责

本轮 `rho-airway-03` 完成五次真实数据拟合，以及 200 次全基因负二项参数模拟
重拟合，R 实际运行 562.6595 秒（9 分 23 秒）。独立 wait 客户端被 SIGTERM 中断后，
CLI 找到原活动 run 与 R PID；重复提交仍返回原 run，原生入口只有一次。终态 Code 0、
已释放、文本完整；原目录与取回副本各 12/12 独立数值／完整性检查通过，五个 RDS
另有 121/121 原生观察检查。四页科学图已检查，自己的 Host 正常清理。

主分析 4,068 个基因 BH < 0.05，六个预选响应基因在五次真实拟合中均为正；模拟
分位数只描述固定四供体及拟合模型下的计数变异，不是种群或临床置信区间。方法、
数值、原始身份、独立检查的限制和证据位置见[事实验收](../examples/real-r-analysis/ACCEPTANCE.md)。

01 的 socket 启动失败、02 的短分析与核验器未就绪导致的收尾失败均保留。02 后来
对原产物的 11/11 检查通过不覆盖原驱动失败；03 用新请求承载新增模拟工作，没有
重跑来替换原失败。已补上核验入口预检。三个副本反例均被拒绝，包括重算摘要后
伪造的 BH 值。这些事实支持先完善消费端分析配方，没有显示 Core 的共同缺口。

当前后续工作收敛为以下两项领域职责，不据此确定新插件包数量。

### 1. R 批分析配方

用户提交明确的数据、脚本与参数，在原 R 进程中完成分析，取回实际 R／包版本、
拟合模型、错误与部分结果。先完善可复用的分析配方、原生条件、资源边界和核对说明，
继续使用维护中的 R 工具与 Core 已有 CLI。03 已说明这条路径无需先创建 R 会话包。

反证与扩张条件：如果实际任务用一个 Rscript 进程及保留的 RDS 就能完成，新建
R-session 包没有新增价值。只有后续任务确实需要定位已有交互 R 内存、处理其输入
或检查原对象身份，而原工具不能提供必要保证时，才单独选择最小原生会话适配。
等待接续不等于宿主替换后的 R 内存恢复，不因 bootstrap 时间较长增加会话平台。

### 2. 科学产物完整性、来源与取回

用户从原 run 找到它实际选定的输出目录，检查完成声明、产物清单与摘要，再通过
普通文件工具读取或复制数值表、图和拟合模型，并核对复制后的字节及科学事实。
Owner 负责清单含义、来源关联和独立核验；Core 的有界 stdout 继续服务执行回报，
不被宣称为科学文件的保存服务。03 的原目录和取回副本核验已经通过；取回清单
含 31 项产物，共 183,546,739 字节，另外保留 manifest 与 complete。

反证与扩张条件：完成标记、manifest 和普通文件工具已经可以承载这条取回流程，
没有证据要求全局 artifact registry。若后续真实任务在跨环境取回、保留或可变来源
上失败，再描述原文件、身份、缺失行为和必要保证，修正实际 Owner 的最小缺口。
不为普通文件读取重新建设 Files 平台，也不将文件名相近推断为科学来源。

## 按事实选择后续变化

先记录用户做了什么、实际发生什么、期望结果、可复现材料、限制属于谁，以及已有
工具为何不能满足。一个环境未装好或已有命令用法错误，不直接构成新插件的理由。
只修选定 Owner 的最小缺口，并保留对应回归；不因试用涉及多个工具就预建统一平台。

本轮试用的已通过、失败和未验证边界见事实验收。后续按用户价值、失败频率与
必要保证选择实际改动。已有 Rscript、R 包、文件工具、Git 或原生任务句柄
足够时直接复用；没有证据就不新增机制。领域方法说明和可调用脚本可以先交付，
不要求先做视图、统一发现服务、MCP／HTTP 入口、编辑器、管理工具或替代聊天产品。

## 仓库责任与后续验收

| Owner | 本轮与后续责任 |
| --- | --- |
| Rho-core | 已声明的受管受理、请求身份、执行持有、事实读取与不重放；只修复真实调用证明的共同缺口 |
| Rho-plugins／实际领域 Owner | R 方法、原生对象与条件、输入和产物语义、科学核对，以及有证据必要的原生适配 |
| Rho 应用 | 选定组件的装配、界面与产品接入；不另建科学执行路径 |
| Agent 环境 | 阅读资料、编写与组合代码、选择工具、管理模型上下文和检查实际反馈 |

三仓独立交付。插件任务不把应用可运行、旧 SDK 刷新或整套旧包通过作为门槛；应用
任务也不能用自己的展示状态解释 R 的执行结果。选定跨仓集成时再明确公共边界、
组件版本、产物与验收，不依赖浮动主分支，也不把单仓通过扩大为完整组合通过。

使用临时项目与独立宿主，不重启用户的 Host 或 R 会话。代码变更做必要的 Owner
行为检查，Cargo 构建和测试串行运行；复用适用的已验证产物。文档变更检查链接和
渲染内容。保留失败、超时和未执行事实，不为得到全绿反复重跑或放宽权限。
